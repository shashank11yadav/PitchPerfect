# API contract

Base path: `/api` (the browser calls it on the web origin; Next.js proxies to the api service).
All request and response bodies are JSON unless noted. Schema names refer to exports of `@pitchperfect/shared`.

## Conventions

- **Auth:** session cookie `pp.sid`. "Student" / "Employer" means a signed-in user with that role; "Verified" additionally requires `emailVerifiedAt`.
- **CSRF:** every non-GET request must send header `x-csrf-token` (value from `GET /api/auth/csrf`, which also sets the paired cookie) **and** an `Origin` matching `APP_URL`. Missing/invalid → `403 csrf_failed`.
- **Errors:** `{ "error": { "code": string, "message": string, "requestId": string, "fields"?: Record<string,string> } }`.

| Status  | `code` values                                                                                                   |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| 400     | `validation_failed`, `invalid_id`, `invalid_token`, `invalid_transition`                                        |
| 401     | `unauthenticated`, `invalid_credentials`                                                                        |
| 403     | `forbidden`, `csrf_failed`, `email_not_verified`, `consent_required`, `company_unverified`, `company_suspended` |
| 404     | `not_found` (also used for resources the caller doesn't own), `not_shared`                                      |
| 409     | `conflict`, `already_applied`                                                                                   |
| 413     | `file_too_large` (also JSON bodies over 100 kB)                                                                 |
| 415     | `unsupported_file`                                                                                              |
| 429     | `rate_limited`, `quota_exceeded`, `budget_exhausted`, `token_limit_reached` (with `Retry-After`)                |
| 500     | `internal_error` (message is always "Something went wrong")                                                     |
| 502/503 | `upstream_error`, `practice_unavailable`                                                                        |

- **Pagination:** list endpoints take `?page=1&pageSize=20` (max 50) and return `{ items, page, pageSize, total }`.

## Health

| Method | Path          | Auth | Response                                                                               |
| ------ | ------------- | ---- | -------------------------------------------------------------------------------------- |
| GET    | `/api/health` | none | `{ status: "ok", db: "ok" \| "down", coach: "ok" \| "down" }` (`HealthResponseSchema`) |

- Liveness only, and always `200`: a down dependency is reported, not raised as an error. It names no versions, uptime, environment, provider or other setting; which practice partner runs is public on its own endpoint, [`GET /api/practice/partner`](#practice).
- The api asks the coach's `/healthz` at most once every 30 s and reuses the answer (shared with `GET /api/practice/partner` and `GET /api/practice/quota`), so health checks don't fan out to the coach.
- 120 requests/minute/IP (`429 rate_limited`), counted in memory per api instance rather than in MongoDB, so the check still answers (with `db: "down"`) when the database can't be reached. A platform prober checking every few seconds stays well under it.

SSE events from `/turns` (each `data:` line is JSON):

- `event: delta` → `{ text }` (the next whole sentence of the partner's reply, already checked)
- `event: retract` → `{ text }` (the reply streamed so far in this turn was withdrawn by a later check; the client removes it and shows `text`, the fallback line, instead. `done` follows with the same text)
- `event: done` → `{ stage: "opening" | "discovery" | "pitch" | "objection" | "close", turnsLeft, finalText }`. `finalText` is the stored, checked reply, and the client replaces the streamed text with it.
- `event: redirect` → `{ text }` (guardrail in-character redirect; turn counted as flagged, and as a strike only when the guards confirmed an attack)
- `event: support` → `{ text }`: the turn signalled suicide or self-harm. `text` is PitchPerfect's own message with crisis resources (the 988 Suicide & Crisis Lifeline and findahelpline.com), sent instead of a reply or a redirect, and the client shows it apart from the partner's lines. The student's text is not stored, the turn is not counted and it is never a strike; tokens the coach spent on it are still charged. A line the shared self-harm rule catches is answered by the api itself, with no coach call and no tokens, right after the body and ownership checks: before the turn rate limit, the token cap, the turn and time limits and an ended session, so none of them can answer it with `ended` or `409` instead.
- `event: ended` → `{ reason: "guard_limit" | "turn_limit" | "expired" }`
- `event: error` → `{ code }`

Turn rules:

- `turnsLeft` = 20 − student turns so far, flagged ones included. The 20th turn's `done` is followed by `ended {reason: "turn_limit"}`; the attempt stays `active` so it can still be ended and scored. Later turns answer only `ended` and never reach the coach.
- After 20 minutes a turn answers only `ended {reason: "expired"}`; ending still scores.
- The third strike is followed by `ended {reason: "guard_limit"}` and the attempt becomes `ended_by_guard`. A redirect is a strike when the coach's event says `strike: true`: a suspect line a second check confirmed as an attack ([practice-partner.md](practice-partner.md#guardrails-packagespartnersrcguardrails)).
- Student text is normalized, clipped, and PII-redacted before it is stored or forwarded (the partner's reply and redirect lines are redacted too). Only the final reply is stored, never the streamed deltas.
- A turn the coach started but never finished (the client left mid-reply, or an `error` event) still counts: the student's text is stored with `flagged: true` and no partner reply, and its usage is charged to the attempt, today's `usagedays` and the student's tokens: what the coach's `error` event reports, or, when there is none (the client left, or the stream broke off), an estimate for the guard, the reply and one moderation check (input ≈ request characters / 4 plus 1,500 tokens of instructions per call, output = their caps, 50 + 200 + 50). A client gone before the turn starts, or a coach that refuses the call outright, costs nothing. The attempt is free for the next turn either way.
- The coach receives the transcript with flagged entries marked `flagged: true` (counted as used turns, never replayed to the model), at most the 40 most recent entries.
- Validation, ownership (`404`), and `409` errors are JSON. Once the stream has started, a failure is an `error` event (`practice_unavailable`, `upstream_error`, or `internal_error`).
- Quota counts session starts, not attempts, in a per-student ledger (`practicestarts`, one row per student and UTC month with a count per UTC day), so deleting an attempt never gives a session back. A start counts whether or not the student took a turn, since each plan costs tokens. Deleting a student account moves the current month's row into `practiceholds`, keyed by an HMAC of the normalized email, until the month ends; a student who signs up with that email the same month gets the counts back.
- A start first reserves a session with one conditional update that checks the daily and monthly limits, and the student's token cap, and counts the start in the same write, so parallel starts can never go over. A refused start (`quota_exceeded`, `token_limit_reached`, or `budget_exhausted`, which gives the session back) leaves the current session untouched.
- It then abandons the student's active attempt and claims a `starting` placeholder. A unique index allows one `starting`/`active` attempt per student, so a parallel start gets `409 conflict` and gives its session back. A failed plan removes the placeholder and gives the session back. A placeholder left by a start that crashed is cleared, and its session given back, by the student's next start once it is 60 s old, or by the purge job once it is 5 minutes old. `starting` attempts are never returned by any endpoint.
- Usage from every coach call (plan, turns, support turns, score) is added to the attempt, to today's `usagedays` row and to the student's tokens for today (`tokens` in their ledger row, per UTC day), failed calls included. A failed plan or score is charged what the coach reports with its error (nothing for a call it turned away), or, when it reports nothing (a timeout or a dropped connection), an estimate of request characters / 4 plus 1,500 tokens of instructions in and the step's output cap out.
- Once the student's tokens today reach `PRACTICE_STUDENT_DAILY_TOKEN_LIMIT` (default 250,000), starts and turns answer `429 token_limit_reached` with `Retry-After` at the next UTC midnight. A turn checks the cap before calling the coach, and since a student has at most one turn in flight, that turn can pass the cap by its own tokens only. Ending and scoring a session in progress still work: the first scoring call is always made; a retry after a failed one is refused at the cap.
- Once today's global usage reaches `PRACTICE_DAILY_TOKEN_BUDGET`, starts and turns answer `429 budget_exhausted` with `Retry-After` at the next UTC midnight; a refused turn calls no coach and costs nothing, and the session can still be ended and scored.

## Employer (`/api/employer`, role Employer)

Every route needs a signed-in employer. Every non-GET route also needs a verified email (`403 email_not_verified`) and counts against a limit of 60 writes/minute/user (`429 rate_limited`). Jobs and applications are looked up through the employer's own company, so another company's ids answer `404 not_found`, exactly like unknown ones.

- **Suspended company:** every route except `GET /api/employer/company` answers `403 company_suspended`: no dashboard, job list or job, no applicants, résumés, scorecards or invites, and no job, company or application changes. The router mounts the check once, after `GET /company`, so every route added later inherits it. Account routes (`/api/me`, `/api/auth/*`) still work, so the user can change their password or delete the account. Lifting the suspension (`npm run admin -- unsuspend-company`) restores access. The company's jobs stay off the public board, job pages, saved jobs and applying the whole time.

- **Company name or domain change:** the badge vouches for a name on a website's domain, so a new `name`, or a `website` on a different registrable domain, turns a `verified` company `unverified`. A company that has had the badge also gets `verificationLockedReason` (`renamed` or `domain_changed`), and from then on only an admin's approval (`npm run admin -- approve-company`) gives the badge back: confirming an email on the domain, signing in, or lifting a suspension does not. An edit never verifies a company, and `suspended` is never changed. A website change that stays on the same registrable domain (a new path or subdomain) keeps the badge.
- **Verified domain:** `PublicCompany` and each job's `company` carry `verifiedDomain`, the registrable domain the badge vouches for (stored when the company is verified, e.g. `"acme-demo.example"`), or `null` when the company isn't verified. The web shows it on the badge.
- **Single-line text:** `name`, a job's `title`, `location` and `skills`, and the profile text fields are one line: line breaks, tabs and other control characters become one space before the length checks.
- **Job status:** `draft → active | archived`, `active ↔ archived`; going back to `draft` is `400 invalid_transition`. The first publish sets `publishedAt`; it is kept on later reactivation. Archiving closes every `applied`/`shortlisted`/`interview` application (`closedReason: "job_archived"`, interview removed) and emails each affected student once. Reactivating does not reopen them.
- **Job edit:** `PATCH` takes only content fields (`JobInputSchema` without `status`); change status through the status endpoint. The slug is created with the job and never changes.
- **Interview:** allowed from `shortlisted` (moves to `interview`) and from `interview` (reschedule); `startsAt` must be in the future and is stored as UTC; the student is emailed. Only a `verified` company may send one (`403 company_unverified`). `meetingUrl` must be `https:` and open Zoom (`zoom.us`, `zoom.com`, `zoomgov.com`), Google Meet (`meet.google.com`), Microsoft Teams (`teams.microsoft.com`, `teams.live.com`), Webex (`webex.com`), Whereby (`whereby.com`), GoTo Meeting (`gotomeeting.com`, `meet.goto.com`), Jitsi Meet (`meet.jit.si`) or Amazon Chime (`chime.aws`), or a subdomain of one, or any host on the company website's registrable domain; anything else, IP addresses and hosts ending in a dot included, is `400` with `fields.meetingUrl`. The list lives in `packages/shared/src/meeting-links.ts`. The email names the host the link opens and the company's verification in plain text. Sent invites count against 20/hour per employer and 3/day per application (`429 rate_limited` with `Retry-After`); a refused request (any `4xx` or `5xx`) doesn't count.
- **Résumé access:** an application carries its own copy of the résumé the student had when they applied, so a later upload never reaches the employer. The employer can download it while the application is `applied`, `shortlisted` or `interview` (always on an active job: archiving closes them), and for 7 days (`LIMITS.resumeAccessGraceDays`) after it became `hired`, `rejected` or `closed`, counted from `endedAt`, which every decision, withdrawal and closing sets (from `updatedAt` when `endedAt` is missing). Never once `withdrawn`. Withdrawing, or the student deleting their résumé, deletes the copy; the purge job deletes copies whose window has passed. An application with no `resumeFileId` field at all falls back to the student's current résumé, under the same window.
- **Applicant view:** application id, status, `savedByEmployer`, `appliedAt`, `interview`, and the student's first/last name, school, major, grad year, `hasResume`, `hasSharedScorecard` (false once the résumé window has closed, like `hasResume`). Never email or any other contact or demographic data. `hasResume` is whether the résumé route would serve a file now (see Résumé access), so it turns false when the window ends.
- **`applicants` (dashboard)** counts open applications (`applied`/`shortlisted`/`interview`) across all of the company's jobs; `interviewsUpcoming` counts `interview` applications whose `startsAt` is in the future; `recentApplications` are the five newest, each with `jobId` and `jobTitle`.

## Internal: api → coach (not reachable from browsers)

Base: `COACH_URL` (e.g. `http://coach:4100`). Every request carries:

- `x-pp-timestamp`: unix seconds
- `x-pp-nonce`: 32 lowercase hex characters (128 random bits), new for every request
- `x-pp-signature`: hex HMAC-SHA256 of `${timestamp}.${nonce}.${METHOD}.${path}.${rawBody}` with `COACH_SHARED_SECRET`, where `METHOD` is the uppercase HTTP method and `path` is the request path exactly as sent, without the query string (e.g. `/v1/plan`). An empty body signs as an empty string.
  Coach answers `401 unauthenticated` if a header is missing or malformed, the signature is wrong, `|now − timestamp| > 60`, or the nonce was already used by a request it accepted (it remembers each nonce until that request's timestamp leaves the window). If its nonce cache is full (100,000 live nonces), it answers `503 practice_unavailable` instead of skipping the check.

| GET    | `/healthz`  | — (unsigned allowed)                                                                                      | `{ status: "ok", provider }`                                                                                                                               |

`usage` = `{ provider, model, inputTokens, outputTokens }`; api adds it to the attempt, to `usagedays` and to the student's tokens. A failed plan or score answers its error JSON with `usage` next to `error` (what its provider calls used before failing), and a turn's `error` event carries the same, so tokens a failed call spent are charged too.

Each `/v1/turn` frame is `event: <type>` followed by `data:` holding the whole `CoachTurnEvent` JSON, `type` included. Validation and input errors are answered as JSON `400` before the stream starts; a failure after that is an `error` event.

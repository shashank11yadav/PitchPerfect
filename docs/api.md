# API contract

Base path: `/api` (the browser calls it on the web origin; Next.js proxies to the api service).
All request and response bodies are JSON unless noted. Schema names refer to exports of `@pitchperfect/shared`.

## Conventions

- **Auth:** session cookie `pp.sid`. "Student" / "Employer" means a signed-in user with that role; "Verified" additionally requires `emailVerifiedAt`.
- **CSRF:** every non-GET request must send header `x-csrf-token` (value from `GET /api/auth/csrf`, which also sets the paired cookie) **and** an `Origin` matching `APP_URL`. Missing/invalid → `403 csrf_failed`.
- **Errors:** `{ "error": { "code": string, "message": string, "requestId": string, "fields"?: Record<string,string> } }`.

| Status  | `code` values                                                                                                   |
| ------- | --------------------------------------------------------------------------------------------------------------- |
| 400     | `validation_failed`, `invalid_id`, `invalid_token`, `invalid_transition`                                        |
| 401     | `unauthenticated`, `invalid_credentials`                                                                        |
| 403     | `forbidden`, `csrf_failed`, `email_not_verified`, `consent_required`, `company_unverified`, `company_suspended` |
| 404     | `not_found` (also used for resources the caller doesn't own), `not_shared`                                      |
| 409     | `conflict`, `email_taken`, `already_applied`                                                                    |
| 413     | `file_too_large` (also JSON bodies over 100 kB)                                                                 |
| 415     | `unsupported_file`                                                                                              |
| 429     | `rate_limited`, `quota_exceeded`, `budget_exhausted`, `token_limit_reached` (with `Retry-After`)                |
| 500     | `internal_error` (message is always "Something went wrong")                                                     |
| 502/503 | `upstream_error`, `practice_unavailable`                                                                        |

- **Pagination:** list endpoints take `?page=1&pageSize=20` (max 50) and return `{ items, page, pageSize, total }`.

## Health

| Method | Path          | Auth | Response                                                                                                                      |
| ------ | ------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/health` | none | `{ status: "ok", db: "ok" \| "down", coach: "ok" \| "down", practicePartner: "scripted" \| "live" }` (`HealthResponseSchema`) |

- Always `200`: a down dependency is data, not an error. `practicePartner` is `scripted` when the coach reports `COACH_PROVIDER=fake` (the offline demo persona, which sends nothing to an AI provider) and `live` otherwise, including when the coach is down or unreachable. The web app reads it to word the practice notice, the persona badge, and the privacy and terms pages. The shared `PracticePartnerKind` type also has `browser`, which only the static demo uses for itself; the api never reports it.
- The api asks the coach's `/healthz` at most once every 30 s and reuses the answer (shared with `GET /api/practice/quota`), so health checks don't fan out to the coach.
- 120 requests/minute/IP (`429 rate_limited`), counted in memory per api instance rather than in Mongo, so the check still answers (with `db: "down"`) when the database can't be reached. A platform prober checking every few seconds stays far under it; the limit only stops floods.

SSE events from `/turns` (each `data:` line is JSON):

- `event: delta` → `{ text }` (the next whole sentence of the partner's reply, already checked)
- `event: retract` → `{ text }` (the reply streamed so far in this turn was withdrawn by a later check; the client removes it and shows `text`, the fallback line, instead. `done` follows with the same text)
- `event: done` → `{ stage: "opening" | "discovery" | "pitch" | "objection" | "close", turnsLeft, finalText }`. `finalText` is the stored, checked reply, and the client replaces the streamed text with it.
- `event: redirect` → `{ text }` (guardrail in-character redirect; turn counted as flagged, and as a strike only when the guards confirmed an attack)
- `event: support` → `{ text }` (the turn signalled suicide or self-harm: `text` is PitchPerfect's own message with crisis resources, the 988 Suicide & Crisis Lifeline and findahelpline.com, sent instead of a reply or a redirect. The student's text is not stored, the turn is not counted (its tokens are still charged, to the student too) and it is never a strike; the client shows it apart from the partner's lines)
- `event: ended` → `{ reason: "guard_limit" | "turn_limit" | "expired" }`
- `event: error` → `{ code }`

Turn rules:

- `turnsLeft` = 20 − student turns so far, flagged ones included. The 20th turn's `done` is followed by `ended {reason: "turn_limit"}`; the attempt stays `active` so it can still be ended and scored. Later turns answer only `ended` and never reach the coach.
- After 20 minutes a turn answers only `ended {reason: "expired"}`; ending still scores.
- The third strike is followed by `ended {reason: "guard_limit"}` and the attempt becomes `ended_by_guard`. A redirect is a strike when the coach's event says `strike: true`: a suspect line a second check confirmed as an attack ([practice-partner.md](practice-partner.md#guardrails-packagespartnersrcguardrails)).
- Student text is normalized, clipped, and PII-redacted before it is stored or forwarded (the partner's reply and redirect lines are redacted too). Only the final reply is stored, never the streamed deltas.
- A turn the coach started but never finished (the client left mid-reply, or an `error` event) still counts: the student's text is stored with `flagged: true` and no partner reply, and its usage is charged to the attempt, today's `usagedays` and the student's tokens: what the coach's `error` event reports, or, when there is none (the client left, or the stream broke off), an estimate for the guard, the reply and one moderation check (input ≈ request characters / 4 plus 1,500 tokens of instructions per call, output = their caps, 50 + 200 + 50). A client gone before the turn starts, or a coach that refuses the call outright, costs nothing. The attempt is free for the next turn either way.
- The coach receives the transcript with flagged entries marked `flagged: true` (counted as used turns, never replayed to the model), at most the 40 most recent entries.
- Validation, ownership (`404`), and `409` errors are JSON. Once the stream has started, a failure is an `error` event (`practice_unavailable`, `upstream_error`, or `internal_error`).
- Quota counts session starts in a per-student ledger (`practicestarts`, one row per student and UTC month with a count per UTC day), not attempts, so deleting an attempt never gives a session back. A start reserves a session with one conditional update that checks the daily and monthly limits and counts the start together, so parallel starts can never go over. It counts whether or not the student took a turn (each plan costs tokens), and while the scenario is still planning. A start reserves its session first, so a refused start (`quota_exceeded`, or `budget_exhausted`, which gives the session back) leaves the current session untouched; then it abandons the student's active attempt and claims a `starting` placeholder; a unique index allows one `starting`/`active` attempt per student, so parallel starts get `409 conflict` and give their session back. A failed plan removes the placeholder and gives the session back, and so does clearing a placeholder older than 60 s (a start that crashed), which the student's next start and the purge job do. `starting` attempts are never returned by any endpoint. Usage from every coach call (plan, turns, support turns, score) is added to the attempt, to today's `usagedays` row and to the student's tokens for today (`tokens` in their ledger row, per UTC day), failed calls included: a failed plan or score is charged what the coach reports with its error (nothing for a call it turned away), or, when it reports nothing (a timeout or a dropped connection), an estimate of request characters / 4 plus 1,500 tokens of instructions in and the step's output cap out. Once the student's tokens today reach `PRACTICE_STUDENT_DAILY_TOKEN_LIMIT` (default 250,000), starts and turns answer `429 token_limit_reached` with `Retry-After` at the next UTC midnight. A start checks it in the same conditional update that counts the start; a turn checks it before calling the coach, and since a student has at most one turn in flight, that turn can go over the cap by its own tokens only. Ending and scoring a session in progress still work.

## Employer (`/api/employer`, role Employer)

Every route needs a signed-in employer. Every non-GET route also needs a verified email (`403 email_not_verified`) and counts against a limit of 60 writes/minute/user (`429 rate_limited`). Jobs and applications are looked up through the employer's own company, so another company's ids answer `404 not_found`, exactly like unknown ones.

- **Suspended company:** every route except `GET /api/employer/company` answers `403 company_suspended`: no dashboard, job list or job, no applicants, résumés, scorecards or invites, and no job, company or application changes. The router mounts the check once, after `GET /company`, so a new route gets it without asking. Account routes (`/api/me`, `/api/auth/*`) still work, so the user can change their password or delete the account. Lifting the suspension (`npm run admin -- unsuspend-company`) restores access. The company's jobs stay off the public board, job pages, saved jobs and applying the whole time.

- **Company name or domain change:** the badge vouches for a name on a website's domain, so a new `name`, or a `website` on a different registrable domain, turns a `verified` company `unverified`. Only an admin's approval (`npm run admin -- approve-company`) gives the badge back; an edit never verifies a company, and `suspended` is never changed. A website change that stays on the same registrable domain (a new path or subdomain) keeps the badge.
- **Job status:** `draft → active | archived`, `active ↔ archived`; going back to `draft` is `400 invalid_transition`. The first publish sets `publishedAt`; it is kept on later reactivation. Archiving closes every `applied`/`shortlisted`/`interview` application (`closedReason: "job_archived"`, interview removed) and emails each affected student once. Reactivating does not reopen them.
- **Job edit:** `PATCH` takes only content fields (`JobInputSchema` without `status`); change status through the status endpoint. The slug is created with the job and never changes.
- **Interview:** allowed from `shortlisted` (moves to `interview`) and from `interview` (reschedule); `startsAt` must be in the future and is stored as UTC; the student is emailed. Only a `verified` company may send one (`403 company_unverified`). `meetingUrl` must be `https:` and open Zoom (`zoom.us`, `zoom.com`, `zoomgov.com`), Google Meet (`meet.google.com`), Microsoft Teams (`teams.microsoft.com`, `teams.live.com`), Webex (`webex.com`), Whereby (`whereby.com`), GoTo Meeting (`gotomeeting.com`, `meet.goto.com`), Jitsi Meet (`meet.jit.si`) or Amazon Chime (`chime.aws`), or a subdomain of one, or any host on the company website's registrable domain; anything else, IP addresses and hosts ending in a dot included, is `400` with `fields.meetingUrl`. The list lives in `packages/shared/src/meeting-links.ts`. The email names the host the link opens and the company's verification in plain text. Sent invites count against 20/hour per employer and 3/day per application (`429 rate_limited` with `Retry-After`); a refused request (any `4xx` or `5xx`) doesn't count.
- **Résumé access:** an application carries its own copy of the résumé the student had when they applied, so a later upload never reaches the employer. The employer can download it while the application is `applied`, `shortlisted` or `interview` (always on an active job: archiving closes them), and for 7 days (`LIMITS.resumeAccessGraceDays`) after it became `hired`, `rejected` or `closed`, counted from `endedAt`, which every decision, withdrawal and closing sets (applications that ended before `endedAt` existed count from `updatedAt`). Never once `withdrawn`. Withdrawing, or the student deleting their résumé, deletes the copy; the purge job deletes copies whose window has passed. Applications made before copies existed have none and use the student's current résumé, under the same window.
- **Applicant view:** application id, status, `savedByEmployer`, `appliedAt`, `interview`, and the student's first/last name, school, major, grad year, `hasResume`, `hasSharedScorecard` (false once the résumé window has closed, like `hasResume`). Never email or any other contact or demographic data. `hasResume` is whether the résumé route would serve a file now (see Résumé access), so it turns false when the window ends.
- **`applicants` (dashboard)** counts open applications (`applied`/`shortlisted`/`interview`) across all of the company's jobs; `interviewsUpcoming` counts `interview` applications whose `startsAt` is in the future; `recentApplications` are the five newest, each with `jobId` and `jobTitle`.

## Internal: api → coach (not reachable from browsers)

Base: `COACH_URL` (e.g. `http://coach:4100`). Every request carries:

- `x-pp-timestamp`: unix seconds
- `x-pp-signature`: hex HMAC-SHA256 of `${timestamp}.${METHOD}.${path}.${rawBody}` with `COACH_SHARED_SECRET`, where `METHOD` is the uppercase HTTP method and `path` is the request path exactly as sent, without the query string (e.g. `/v1/plan`). An empty body signs as an empty string.
  Coach rejects if the signature is wrong or `|now − timestamp| > 60`.

| Method | Path        | Body (shared schema)                                                                                      | Response                                                                                                                                                   |
| ------ | ----------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/healthz`  | — (unsigned allowed)                                                                                      | `{ status: "ok", provider }`                                                                                                                               |
| POST   | `/v1/plan`  | `CoachPlanRequest` `{ skill, targetRole?, industry?, job?: { title, descriptionText, skills[] } }`        | `CoachPlanResponse` `{ scenarioPublic, scenarioPrivate, usage }`                                                                                           |
| POST   | `/v1/turn`  | `CoachTurnRequest` `{ skill, scenarioPublic, scenarioPrivate, transcript[], studentText, currentStage? }` | SSE: `delta {text}`, `retract {text}`, `done {stage, finalText, usage}`, `redirect {text, strike, usage}`, `support {text, usage}`, `error {code, usage?}` |
| POST   | `/v1/score` | `CoachScoreRequest` `{ skill, scenarioPublic, scenarioPrivate, transcript[] }`                            | `CoachScoreResponse` `{ scorecard: Scorecard, usage }`                                                                                                     |

`usage` = `{ provider, model, inputTokens, outputTokens }`; api adds it to the attempt, to `usagedays` and to the student's tokens. A failed plan or score answers its error JSON with `usage` next to `error` (what its provider calls used before failing), and a turn's `error` event carries the same, so tokens a failed call spent are charged too.

Each `/v1/turn` frame is `event: <type>` followed by `data:` holding the whole `CoachTurnEvent` JSON, `type` included. Validation and input errors are answered as JSON `400` before the stream starts; a failure after that is an `error` event.

# Design trade-offs and roadmap

The decisions below each pick one side of a trade-off on purpose. Each row gives the reasoning and the next step.

## Sign-in and account safety

| Decision                                                                                            | Why                                                                                                                                                                                                                                                                                                                                                           | Next step                                                                                        |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Failed sign-ins share one budget per email: 10 per 15 minutes from all addresses                    | Guessing is capped at 40 tries an hour per account, which a 12-character password outside the breached list survives. Someone spreading attempts over many addresses makes new browsers wait out the window, but a browser that signed in to the account before (a signed device cookie) still gets in, and the owner is emailed a reset link once per window | Let the owner request a one-time sign-in link for a new browser                                  |
| Failed sign-ins are also capped per address: 30 per 15 minutes, IPv6 per /64                        | Credential stuffing from one address is held to 120 tries an hour. Successful sign-ins never count, so a shared campus or office network only waits after a burst of failures                                                                                                                                                                                 | Let browsers with the device cookie above skip it too                                            |
| Forgot-password is limited to 3 requests an hour per email                                          | It stops reset-email floods against one inbox. The only thing that can be delayed is the reset link itself                                                                                                                                                                                                                                                    | Add a per-address limit alongside it, and let a signed-in user change their password in settings |
| Sign-up with a registered email answers `201` and notifies that address                             | The response never reveals which emails have accounts, and the real owner learns someone tried. Repeats are bounded by the 3-per-hour sign-up limit                                                                                                                                                                                                           | Send that notice at most once an hour per address                                                |
| An email change waits for the new address to confirm it, whether or not that address has an account | The answer, its timing and `/api/auth/me` are the same either way, so the change can't be used to test for accounts; the address changes only when its link is followed, and only if it is still free                                                                                                                                                         | Let the account owner cancel a pending change from settings                                      |
| Students are 18 or older                                                                            | It keeps minors' data out of the system without guardian consent flows                                                                                                                                                                                                                                                                                        | Guardian or school consent for school programs                                                   |

## Practice partner

| Decision                                                                          | Why                                                                                                                                                                                                                                                                                                                                       | Next step                                                                                                            |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| A guard strike needs two checks to agree                                          | Ordinary sales lines never end a session. A line only one check flags is still redirected every time, so an attacker gains nothing but turns, and the session ends at 20 turns regardless                                                                                                                                                 | Have the model guard return a confidence and count confident verdicts on their own                                   |
| Leak checks are rules over canonical readings of the reply                        | They see through look-alike letters, leetspeak, separators, reversed and encoded text, invisible tag characters, spelled-out letters and splits across sentences and across the session's replies, and run in the browser demo too. Translation and paraphrase are the remaining class; the canary has no meaning to translate            | Give the moderator a leak classifier that sees the hidden scenario                                                   |
| Replies are moderated sentence by sentence, two checks at a time                  | Streaming starts after the first sentence's check, and the 80-word and 600-character caps bound a reply to one check per sentence within them, plus one for the whole reply. A reply cut at a cap ends the stream there, so a stage marker the model would have written after it is not read and the stage comes from the call's position | Moderate short sentences together, so a reply of many short sentences costs fewer checks                             |
| Self-harm detection runs a first-person pattern list first                        | The api can answer a student in crisis before any limit, model call or token. With a live provider the model guard catches other wording; without one, unclear lines get a gentle check-in. A false positive costs one support message and no turn. Seven languages are covered                                                           | A dedicated classifier call for borderline turns, reviewed through the logged `support` outcomes, and more languages |
| A planned scenario that fails its check falls back quietly                        | The student still gets a safe call for the skill and job title, and the coach logs `scenario_flagged`                                                                                                                                                                                                                                     | Mark the job for review and tell the employer what was removed                                                       |
| The daily token budget is checked before every start and turn, not before scoring | A spent budget stops new calls at once, but a session in progress still gets its scorecard. With one turn in flight per student, the most the budget can go over is the turns and scores already running                                                                                                                                  | Reserve an estimated session cost at start and refund what is unused at the end                                      |
| Voice uses the browser's speech APIs                                              | No audio reaches PitchPerfect's servers and there is no speech bill. Browsers without speech recognition, such as Firefox, use text                                                                                                                                                                                                       | Server-side speech-to-text and text-to-speech behind the coach, with streaming audio                                 |

## Employers and hiring

| Decision                                                                                     | Why                                                                                                                                                                                                                                           | Next step                                                                            |
| -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| One employer user per company                                                                | No one can take over another employer's company, and there is no invite flow to secure                                                                                                                                                        | `companymembers` with roles, invite tokens and ownership transfer                    |
| Automatic verification checks the email domain, not the name                                 | The badge means the poster controls the website's domain, and it names that domain, so a famous name on someone else's domain is plain to see. A rename or a move to another domain drops the badge, and only an admin approval gives it back | Hold names that match well-known brands for an admin before the badge is granted     |
| Interview links must be on a known meeting service or the company's own domain               | Invites can't point at look-alike login pages. A company on another tool can host the link on its own domain                                                                                                                                  | Let an admin extend the list without a release                                       |
| Résumé access ends 7 days after a decision                                                   | A student's file doesn't stay with every employer they applied to; an employer who needs it downloads it in that window                                                                                                                       | Let a hired student share their résumé with that employer for longer                 |
| Suspending a company leaves its applications as they are                                     | Suspensions are rare and can be lifted, and closing would email every applicant                                                                                                                                                               | Close open applications on suspension with their own reason and notify students once |
| A suspended company's owner email and verified domain stay held after the account is deleted | Deleting and signing up again doesn't start a suspended company over. The hold keeps only keyed hashes of the emails and the domain, and only a verified domain is held, so typing someone else's website can't block their domain            | Expire holds an admin hasn't lifted after a set time                                 |
| Admin runs from a CLI                                                                        | The operational surface stays small and needs no extra authenticated app                                                                                                                                                                      | An admin app behind SSO when moderation volume calls for it                          |

## Platform

| Decision                                          | Why                                                                                                                                     | Next step                                                                                   |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Rate-limit counters live in MongoDB               | Every api instance shares them with no extra service. `/api/health` counts in memory so it answers when the database is down            | Move the counters to Redis; `middleware/rate-limit-store.ts` is the one place to change     |
| Cookies are `__Host-` prefixed only in production | Browsers refuse the prefix over plain http, so local development keeps the plain names; the web app accepts either session cookie name  | Serve local development over https and use one set of names                                 |
| GitHub Actions are pinned to commit SHAs          | A moved tag can't change what CI runs. Dependabot keeps the SHAs and their version comments current, and CI fails on an unpinned action | Pin the CI service and Docker base images by digest too                                     |
| One light theme                                   | Components use design tokens only                                                                                                       | A dark token set                                                                            |
| English content, prompts and rubric               | The lessons, persona prompts and scoring rubric are written and checked in one language; student location is a US state                 | Localized lessons and prompts, a `locale` on attempts, and country plus region for location |

## Before a public launch

- Replace the `/privacy` and `/terms` templates with text reviewed by counsel. They already describe the real data flows.
- Add a data export, `GET /api/me/export` (JSON plus the résumé), alongside the existing account deletion.
- Add threaded employer–student messages with moderation, next to the interview emails.
